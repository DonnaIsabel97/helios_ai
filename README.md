# Helios

**AI-Powered Financial Risk Analysis & Decision-Support Platform**

Helios is a full-stack AI application designed to integrate machine learning and probabilistic AI models into structured financial risk workflows.

The platform combines two complementary AI systems:

* **FinGuard** — an XGBoost-based fraud detection model designed to identify potentially fraudulent financial transactions.
* **FinSage** — a Bayesian Network model designed to evaluate credit risk through probabilistic inference.

Rather than presenting model predictions as isolated outputs, Helios is designed around **role-based review and approval workflows**. Each model has its own specialized dashboard where authorized users can analyze results, add notes, review cases, submit decisions for approval, and perform actions according to their assigned role.

Helios was developed from AI/ML work completed during my graduate studies in Computer Science, Artificial Intelligence, and Machine Learning, with the goal of exploring the engineering required to move trained AI models toward a deployable, full-stack application.

> **Project Status:** Helios is under active development. The AI models and core backend architecture are implemented. The frontend dashboard integration is currently being restored and the role-based workflow architecture is being expanded.

## Overview

Helios connects **machine learning, probabilistic AI, full-stack engineering, and human decision workflows** within a single platform.

The application is organized around two specialized environments:

### FinGuard Dashboard

The FinGuard dashboard supports fraud-detection analysis and the workflows surrounding potentially fraudulent transactions.

It is designed to allow authorized users to:

* Analyze FinGuard predictions
* Review flagged transactions
* Add case notes
* Track review status
* Submit cases for approval
* Approve or reject cases when authorized
* Perform additional fraud-specific workflow actions

### FinSage Dashboard

The FinSage dashboard supports credit-risk analysis using the probabilistic outputs generated by FinSage.

It is designed to allow authorized users to:

* Analyze credit-risk assessments
* Review model results
* Add notes and supporting information
* Track case status
* Submit cases for approval
* Approve or reject decisions when authorized
* Perform additional credit-risk-specific workflow actions

This design treats AI predictions as **decision-support information within a controlled human workflow**, rather than as automatic final decisions.

## AI Models

### FinGuard — Fraud Detection

FinGuard is a supervised machine learning model designed to identify potentially fraudulent financial transactions.

The model uses **XGBoost** for binary classification and addresses the severe class imbalance commonly found in fraud-detection datasets.

Its development pipeline includes:

* Data preprocessing and feature preparation
* Stratified train/test splitting
* Feature scaling
* SMOTE-based class balancing
* XGBoost classification
* Hyperparameter optimization with GridSearchCV
* Precision, recall, F1, and ROC-AUC evaluation
* Confusion matrix analysis
* Model persistence for application integration

FinGuard emphasizes identifying fraudulent activity while maintaining sufficient precision to reduce unnecessary fraud alerts.

---

### FinSage — Credit Risk Analysis

FinSage uses a **Discrete Bayesian Network** to model probabilistic relationships between financial variables and estimate credit-risk classifications.

Its development includes:

* Feature selection and preprocessing
* Target transformation
* Feature discretization
* Expert-designed Bayesian Network structure
* Maximum Likelihood parameter estimation
* Probabilistic inference
* Variable elimination
* Model evaluation and optimization
* Model persistence

An expert-designed network structure was selected because the development dataset was relatively small. This provides greater control over modeled relationships while maintaining interpretability.

Automatic structure learning remains a potential direction for future experimentation with larger datasets.

---

### Why Two Models?

FinGuard and FinSage demonstrate two different approaches to financial AI:

| Model        | Problem                | AI Approach                 | Primary Technology |
| ------------ | ---------------------- | --------------------------- | ------------------ |
| **FinGuard** | Fraud Detection        | Supervised Machine Learning | XGBoost            |
| **FinSage**  | Credit Risk Assessment | Probabilistic AI            | Bayesian Network   |

FinGuard emphasizes **predictive classification**, while FinSage emphasizes **probabilistic reasoning and interpretability**.

Helios provides the application layer that brings these different AI approaches into structured, human-controlled workflows.

## Authentication & Role-Based Access

Helios is designed around **authentication and role-based access control (RBAC)**.

Authentication determines the identity of the user, while authorization determines which operations that user is permitted to perform.

Different roles can therefore interact with the same FinGuard or FinSage case while having different permissions.

For example:

* A reviewer may inspect a model result, add notes, and perform an initial review.
* A reviewer may submit a completed case to an authorized approver.
* An approver may evaluate the submitted case and approve, reject, or return it for additional review.
* Higher-level users may have broader visibility and decision-making permissions.
* Sensitive actions can be restricted to explicitly authorized roles.

The intended approach is comparable to a **policy-controlled code review workflow**, where defined permissions determine who can review, submit, approve, and finalize an action.

> **RBAC implementation in progress:** Final role definitions, permission policies, and authorization rules will be documented as the access-control architecture is finalized.

## Review & Approval Workflow

AI predictions in Helios are intended to initiate or support a workflow rather than automatically produce a final business decision.

A simplified case lifecycle may follow:

```text
                    AI Analysis
                         │
                         ▼
                  Pending Review
                         │
                         ▼
                 Reviewer Analysis
                  │            │
             Add Notes     Review Data
                  │            │
                  └─────┬──────┘
                        │
                        ▼
              Submit for Approval
                        │
                        ▼
                 Approver Review
                        │
              ┌─────────┼─────────┐
              │         │         │
              ▼         ▼         ▼
          Approved   Rejected   Changes
                                Requested
                                    │
                                    ▼
                              Back to Review
```

The exact workflow may differ between FinGuard and FinSage because each model addresses a different financial problem.

This architecture is intended to provide **human oversight, traceable decisions, and controlled authorization** around AI-assisted analysis.
